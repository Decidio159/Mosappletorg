# Работа с заготовками Decidio

Этот файл копируется в папку каждого нового проекта клиента — тогда он
подхватывается автоматически и всё нижесказанное действует с первой минуты.

## Порядок сборки макета

1. **Прочитать `бриф.md` в папке проекта.** Если его нет или он пустой —
   задать вопросы из шаблона `заготовки для сайтов/бриф.md` **одним разом**
   и только потом начинать. Каждый круг правок после показа стоит дороже,
   чем вопрос в начале.
2. **Прочитать `каркасы/_общее/ШПАРГАЛКА.md`.** Там все классы, все
   `data-`хуки, токены темы, контракт формы и корзины. **Не читать
   `base.css`, `blocks.css`, `effects.css` и скрипты целиком** — в шпаргалке
   есть всё, что нужно для сборки. Открывать исходники только если правишь
   сам скелет.
3. Развернуть папку: `инструменты/новый-проект.py --имя "Клиент" --ниша ниша`.
   Он сам копирует каркас, скелет, шрифты и памятки и правит `@import`
   шрифтов под новую глубину. Многостраничнику — ключ `--многостраничный`,
   тогда страницы собираются из `_шаблоны/`, а не копируются руками.
4. Собрать страницы, заменить всё, что помечено капсом и комментариями
   `ЗАМЕНИТЬ`.
5. Прогнать аудит (см. ниже) и только потом показывать.

## Правила скелета

- **Ниша меняет только `theme.css`** — восемь цветов и пара шрифтов.
  Новый блок идёт в `_общее/css/blocks.css` и становится общим для всех.
- **Никаких внешних библиотек и никаких запросов на сторонние домены.**
- Два шрифтовых файла на макет, не больше.
- Анимации только через `transform` и `opacity`.
- Иконки — из `icons/`, вставляются инлайном.
- Все комментарии в коде и все файлы проекта — по-русски.
- **Все видимые заглушки обращены к клиенту.** «Здесь будет карта проезда
  к вашему салону», «Здесь будет ваше фото», «Здесь будут ваши товары» —
  и коротко, что для этого прислать. Инструкции самому себе («Конструктор
  карт → HTML-код») живут в HTML-комментариях: клиент их не видит.

## Что проверить перед показом

Весь макет разом проверяет `инструменты/проверка.py --проект "папка"` —
он сам поднимает сервер, обходит страницы и пишет отчёт. Одну страницу
глазами — `инструменты/аудит.js`: открыть страницу, F12 → «Консоль»,
вставить файл целиком. Для проверки мобильных ширин макет должен открываться
по http — `python -m http.server 8000` в папке макета. Список того, что он
смотрит, он же ручной чеклист:

- горизонтальная прокрутка на **320, 375 и 1280 px** — её не должно быть
  ни на одной странице;
- все внутренние ссылки ведут на существующие файлы, битых картинок нет;
- контраст мелких подписей (`--text-dim`) не ниже 4,5:1 на `--bg` и на `--bg-soft`;
- кликабельные элементы не меньше 44 px;
- работают: бургер, фильтры каталога, корзина, обе формы;
- в консоли пусто;
- фотографии в WebP, каталог целиком не тяжелее 500 КБ.

## Про макет и сдачу

Макет показывается клиенту бесплатно и до договорённости, поэтому:

- в шапке каждой страницы стоит `noindex, nofollow` с пометкой `МАКЕТ`;
- форма не отправляется по-настоящему, если подключён `общее/js/demo.js`
  (ключ `--демо` у `новый-проект.py`). На хостинге с PHP его не подключаем:
  тогда `send.php` работает всерьёз и пятый пункт чеклиста проверяется;
- почта в `send.php` по умолчанию не клиентская, её меняют при сдаче.

Всё перечисленное переключает `инструменты/сдача.py`: сначала без ключей —
посмотреть список, потом с `--делать`.

Всё это перечисляется в `ПРОЧТИ МЕНЯ.md`, который кладётся в папку проекта.

## Чего не делать

- Не переписывать заново то, что уже есть в `_общее/` — сначала проверить
  по шпаргалке.
- Не делать руками то, для чего есть скрипт в `инструменты/`: товары из ВК,
  ресайз фото, карточки каталога, сборка страниц, аудит.
- Не хранить одинаковую шапку и подвал в шести файлах руками, если в папке
  есть `_шаблоны/` и сборщик.
- Не изобретать классы под то, для чего в скелете уже есть блок.
